## 1. 工作流（一个对话完成一个 issue）

**设计对话**（一个需求一个或多个对话）：

1. 从 §3 需求池选定一条「待设计」条目（或新追加一条，一行即可不展开）
2. 按 AGENTS §9：先读 GAME-DESIGN 相关章节与 ARCHITECTURE 定位代码，再讨论方案
3. 定稿后：设计规则回写 GAME-DESIGN 对应章节；本条目状态改为「已拆解」并补齐 issue 表

**开发对话**（一个对话一个 issue）：

1. 开工：目标 issue 状态改为「开发中」
2. 按 AGENTS §5 TDD 实现，运行验收命令
3. 收尾（必须同一对话内完成）：
   - 代码提交：`feat|fix: R<需求号>-<序号> 简述`
   - 将 commit hash、日期、验收证据回填 issue 条目，状态改为已完成
   - 触及设计规则 → 回写 GAME-DESIGN；触及文件/职责/接口 → 回写 ARCHITECTURE
   - 文档以并入同一提交或紧随的 `docs:` 提交落地
4. 需求下全部 issue 完成 → 需求条目状态改为「已完成」

单点 bug 修复可建只含一个 issue 的需求条目，走轻量路径（AGENTS §2）。

## 2. 状态机与守则

- 需求条目：`待设计 → 已拆解 → ✅ 已完成`；异常出口 `搁置` / `已拒绝`（注明原因与日期）
- issue：`待开发 → 开发中 → ✅ 已完成`；异常出口 `已取消`（需求变更时注明替代者）
- 状态变更为「已完成」必须有当轮验证证据（AGENTS §6），证据不足不得标记
- 同一时间最多一个 issue 处于「开发中」（单人开发，文档一致性优先）；确需并行先征得用户确认
- 完成条目原地保留，作为版本管理台账；数量过多时再议归档
- 文件有增删的 issue 收尾时必跑 ARCHITECTURE 覆盖率检查（见 ARCHITECTURE §4）

  - 议题①部分定稿（2026-09-08）：技能组织 = **三注册表并列**（SKILLS 物理攻击 + 行为技能 / SPELLS 法术 / TRAIT_CONFIGS 被动 + 职业强化），行为技能进 SKILLS（非法术主动，多一个行为效果声明字段，结构随议题④定）；通用池 = 三表可学条目的 union 视图（合并枚举函数），不建统一单表
  - 议题①AoE 定稿（2026-09-08）：AoE 为技能/法术可选「效果区域」声明（缺省单体，如半径 1 六边形圆盘），叠加于 target 维度（enemy+area = 敌方群体、ally+area = 群体治疗）；误伤规则 = **只影响目标阵营**（敌方 AoE 不伤友军、友方 AoE 不惠及敌方）；**AoE 目标选择 = 选释放位置（格子）而非单位**——射程按施法者到中心格计、空格可释放，区域内按阵营筛受影响者、逐单位独立命中结算；AoE 法术不触发反击（法术线现状延伸）；首版内容 = 陨石术改 AoE（威力数值随议题⑤内容清单重定）；§8「AoE 法术不做」随 R8 定稿修订
  - 议题①F1~F4 定稿（2026-09-08，议题①闭合）：F1 SKILLS 增 `target: 'enemy'|'self'|'ally'` 三值 + 效果声明四段（伤害/治疗/状态施加/行为，每技能单效果，治疗与状态段复用法术现有结构），target=ally/self 必中（不掷命中不吃距离惩罚，§4.12 增益口径扩展）；F2 TRAIT_CONFIGS 增 learnable 标记（true=通用被动进池 / false=职业强化仅模板引用）；F3 SKILLS/SPELLS 增可选 `resourceType?`/`weaponType?` 声明字段，缺省豁免；F4 通用池 = SKILLS ∪ SPELLS ∪ TRAIT_CONFIGS(learnable)，我方 UI 主动双过滤 + 被动免过滤，敌方关卡配置校验同双过滤
  - 议题②部分定稿（2026-09-08）：武器过滤「声明即过滤」修订与背刺限匕首已入 R3 台账；**领主武器默认不带盾**（= 剑），**盾突从领主技能中移除**（领主出厂 = 横斩，防战保留剑盾 + 盾突）；**突刺不共用、拆分**——突刺收窄为枪系专用（骑士/飞马/枪兵），盗贼新增专属刺技（暂名「刺击」，限匕首，数值随议题⑤内容清单定）；**武器线不绑定单一伤害线（定稿）**——差异化在技能层实现：同武器线的技能可跨伤害线（剑系可配突伤害技能、斧系可配钝伤害技能），武器只决定可学技能集，伤害类型由技能自带；具体跨线技能随议题⑤内容清单设计，§4.2 三线矩阵不动
  - 议题②数组语义定稿（2026-09-08）：武器原子 8 种（剑/盾/锤/匕首/枪/斧/弓/杖）；角色武器 = 原子数组，**任意组合合法**（剑盾/锤盾/枪盾/单原子等），结构不设组合白名单，组合由模板与装备配置自由决定；技能声明所需武器（单值或 one-of 数组），匹配 = 所需 ∈ 角色武器集；17 模板武器映射按已纠正版本定稿（领主=剑、防战=剑盾、防骑=锤盾、盗贼=匕首、骑士/飞马=枪、斧兵=斧、弓箭=弓、牧师/法师/敌方法师=杖、敌方同位同武器、BOSS=锤），后续组合调整留内容轮

  - 议题④定稿（2026-09-09，潜行类行为技能机制）：**绝对隐身**——对敌阵营不可见、不可选中为单体目标、AoE 区域筛受影响者时直接排除，无邻格/侦查发现判定；**取消时机 = 三类主动行为**（移动/攻击/使用技能）即取消，**歇息不取消、跨回合维持**（潜行蹲草回资源玩法成立）；**敌方 AI 交互 = 感知全忽略 + 物理存在保留**——警戒扫描不含潜行单位、择优不可选为目标（含落位计算）、「向最近我方单位移动」不计潜行单位；潜行单位**仍占格：不可经过、不可停留、不可落位**（复用现有单位阻挡逻辑，潜行封路战术成立）；**规则对称、首版不配**——潜行语义对任意阵营一致（敌方若潜行对我方隐藏渲染、不可选中），首版 17 模板不配敌方潜行；**真实视野反制被动**：通用被动进池（TRAIT_CONFIGS learnable），新增声明字段 `revealRange: N`（数值随数值期），持有者周围 N 格内潜行单位对**持有者所在阵营**可见、可选中攻击，潜行状态**不取消**（出范围自动重新隐匿，「被发现」≠「被打破潜行」），敌方持有则警戒/择优按普通单位处理
