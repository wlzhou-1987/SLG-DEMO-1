## 1. 工作流（一个对话完成一个 issue）

**设计对话**（一个需求一个或多个对话）：

1. 从 §3 需求池选定一条「待设计」条目（或新追加一条，一行即可不展开）
2. 按 AGENTS §9：先读 GAME-DESIGN 相关章节与 ARCHITECTURE 定位代码，再讨论方案
3. 定稿后：设计规则回写 GAME-DESIGN 对应章节；本条目状态改为「已拆解」并补齐 issue 表

**开发对话**（一个对话一个 issue）：

1. 开工：目标 issue 状态改为「开发中」
2. 按 AGENTS §5 TDD 实现，运行验收命令
3. 收尾（必须同一对话内完成）：
   - 代码提交：`feat|fix: R<需求号>-<序号> 简述`
   - 将 commit hash、日期、验收证据回填 issue 条目，状态改为已完成
   - 触及设计规则 → 回写 GAME-DESIGN；触及文件/职责/接口 → 回写 ARCHITECTURE
   - 文档以并入同一提交或紧随的 `docs:` 提交落地
4. 需求下全部 issue 完成 → 需求条目状态改为「已完成」

单点 bug 修复可建只含一个 issue 的需求条目，走轻量路径（AGENTS §2）。

## 2. 状态机与守则

- 需求条目：`待设计 → 已拆解 → ✅ 已完成`；异常出口 `搁置` / `已拒绝`（注明原因与日期）
- issue：`待开发 → 开发中 → ✅ 已完成`；异常出口 `已取消`（需求变更时注明替代者）
- 状态变更为「已完成」必须有当轮验证证据（AGENTS §6），证据不足不得标记
- 同一时间最多一个 issue 处于「开发中」（单人开发，文档一致性优先）；确需并行先征得用户确认
- 完成条目原地保留，作为版本管理台账；数量过多时再议归档
- 文件有增删的 issue 收尾时必跑 ARCHITECTURE 覆盖率检查（见 ARCHITECTURE §4）

### R4 属性体系与伤害公式（状态：已拆解）
- 来源：用户提议（战前准备联动功能讨论引出，2026-09-07 设计定稿；资源/地形效果/暴击已拆至 R5/R6/R7）

- 设计结论（已定稿 2026-09-07，规则已回写 GAME-DESIGN §3/§4.1~§4.5/§4.9/§4.11/§4.12/§5/§7.3/§8；本节保留决策台账）：
  - 攻→力量/魔力；防→物防/魔防；技=命中；运=回避（+R7 双向暴击）；速=追击/回避驱动/先攻反击/部分技能伤害基数（四职责，属性预算须定高价）
  - 统一伤害结构（定稿 2026-09-07）：物理/魔法/治疗共用「伤害段」结构 {属性权重表, 固定值, 伤害线}；法术公式为其单属性特例（权重 {魔力: 法术伤害系数} + 法术固定伤害），不维护两套结构；段数组为多段（双伤害）预留，DEMO 限制恰好 1 段
  - 统一伤害公式（定稿）：伤害 = max( ((Σ 属性×权重) + 固定值) × 克制系数 − 防御项 − 地形防, 0 )；克制乘算位于 max 内（先乘后减）；物理段防御项=物防、地形防=地形物理防、克制系数含护甲矩阵；魔法段防御项=魔防×魔防系数、地形防=地形法术防、克制系数为法术级克制；治疗用同结构、不扣防御项
  - 技能伤害基数（组合权重）：技能配置属性权重（如 {技巧:1, 速度:0.5}）加权合成；减伤轴由伤害线决定（物理线→物防、魔法线→魔防），与基数属性解耦；缺省权重取职业默认（R4 落地时「模板即职业」过渡——UnitTemplate 即职业事实源，实体化见 R8）
