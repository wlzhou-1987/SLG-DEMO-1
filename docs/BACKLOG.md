# 需求池与进度（BACKLOG）

> 状态：活文档，M6 之后唯一的进度真源。
> 历史里程碑 M1~M6 已冻结，见 [AGENTS.md §10](../AGENTS.md) 与 [GAME-DESIGN.md §10](GAME-DESIGN.md)。
> 状态标注沿用项目惯例：`✅ 已完成（日期，验收证据）`。

## 1. 工作流（一个对话完成一个 issue）

**设计对话**（一个需求一个或多个对话）：

1. 从 §3 需求池选定一条「待设计」条目（或新追加一条，一行即可不展开）
2. 按 AGENTS §9：先读 GAME-DESIGN 相关章节与 ARCHITECTURE 定位代码，再讨论方案
3. 定稿后：设计规则回写 GAME-DESIGN 对应章节；本条目状态改为「已拆解」并补齐 issue 表

**开发对话**（一个对话一个 issue）：

1. 开工：目标 issue 状态改为「开发中」
2. 按 AGENTS §5 TDD 实现，运行验收命令
3. 收尾（必须同一对话内完成）：
   - 代码提交：`feat|fix: R<需求号>-<序号> 简述`
   - 将 commit hash、日期、验收证据回填 issue 条目，状态改为已完成
   - 触及设计规则 → 回写 GAME-DESIGN；触及文件/职责/接口 → 回写 ARCHITECTURE
   - 文档以并入同一提交或紧随的 `docs:` 提交落地
4. 需求下全部 issue 完成 → 需求条目状态改为「已完成」

单点 bug 修复可建只含一个 issue 的需求条目，走轻量路径（AGENTS §2）。

## 2. 状态机与守则

- 需求条目：`待设计 → 已拆解 → ✅ 已完成`；异常出口 `搁置` / `已拒绝`（注明原因与日期）
- issue：`待开发 → 开发中 → ✅ 已完成`；异常出口 `已取消`（需求变更时注明替代者）
- 状态变更为「已完成」必须有当轮验证证据（AGENTS §6），证据不足不得标记
- 同一时间最多一个 issue 处于「开发中」（单人开发，文档一致性优先）；确需并行先征得用户确认
- 完成条目原地保留，作为版本管理台账；数量过多时再议归档
- 文件有增删的 issue 收尾时必跑 ARCHITECTURE 覆盖率检查（见 ARCHITECTURE §4）

### R4 属性体系与伤害公式（状态：待设计）
- 来源：用户提议（战前准备联动功能讨论引出，2026-09-07 设计对话进行中；资源/地形效果/暴击已拆至 R5/R6/R7，设计时兼顾三者）
- 一句话：六维属性（HP/攻/防/速/技/运）改造为八维战斗属性（HP/力量/魔力/物防/魔防/速/技/运），物理/魔法双线伤害公式，组合权重伤害基数（MP 作为资源属性归 R5）
- 设计结论（框架讨论中，定稿后回写 GAME-DESIGN 并拆 issue）：
  - 攻→力量/魔力；防→物防/魔防；速=追击、技=命中、运=回避（命中回避体系拆分待专项讨论）
  - 技能伤害基数（组合权重）：技能配置属性权重（如 {技巧:1, 速度:0.5}）加权合成；减伤轴由伤害线决定（物理线→物防、魔法线→魔防），与基数属性解耦；缺省权重取职业默认（R4 落地时「模板即职业」过渡——UnitTemplate 即职业事实源，实体化见 R8）；双伤害叠加以「伤害段」形态预留：技能伤害结构采用段数组（每段=权重+固定值+伤害线），DEMO 限制恰好 1 段、不实现多段技能/职业
  - 魔法伤害公式：直接伤害 = max((魔力 × 法术伤害系数 + 法术固定伤害) × 克制系数 − 魔防 × 魔防系数 − 地形法术防, 0)；魔防系数默认 1、可被职业/被动技能修正（预留挂点）；DoT 每回合伤害 = max(1, floor(直接结果 ÷ 持续回合数))、末回合补足余数（此前合计不足直接结果时补差），max(1,·) 保底与系数调参带来的小幅总伤溢价为接受设计（意图：DoT 总伤略高于同位直伤、且每回合不跳 0）
  - 治疗量：按技能差异化公式，主要挂魔力
  - 物理线保留护甲矩阵：只看伤害类型 × 护甲类型，不考虑距离；矩阵重构数值待议
  - 克制架构统一：护甲克制——物理走矩阵（伤害类型×护甲）、魔法走法术级克制系数；兵种克制（克飞行/克骑兵）——技能/装备级配置，物理魔法通用；需轻量兵种标签（飞行已有、骑兵待标签化）
  - 射程属性条件加成（§4.4/§4.12 原留白）：弓挂力量、法术挂魔力，阈值规则可配；弓手属性价值分配方向——技供命中、实际射程越远命中惩罚越高、命中溢出 100% 部分转暴击（换算率与叠加规则随 R7 定）
  - 近战/远程判定（定稿）：仅对物理伤害与物理技能生效，按攻击发生时双方距离判定（距离 1=近战、≥2=远程）；法术线不区分近远程
  - 地形防字段以 R6 设计为准：物理线用地形物理防、魔法线用地形法术防（已补入魔法公式）；R4 先于 R6 实现时，将现地形 defense 字段重命名为物理防过渡，R6 只新增其余字段
  - 属性死值面接受：法系的力量、物理系的魔力、非法术职业隐藏的 MP 均为当前死属性，为潜在转职激活预留；模板数值设计不为死属性付费
  - 实现备忘：无当前消费者的规则（如近战/远程判定）不写分支代码，等首个真实消费者出现再落逻辑
  - 待议：物理伤害公式结构（组合权重基数与 power/矩阵的运算顺序）、矩阵重构数值、命中回避体系拆分（专项讨论）、克制系数配置结构与兵种标签轻量方案、延伸射程（属性/地形加出）是否吃距离命中惩罚（建议吃，形成取舍）、DoT 结算快照（施放时锁定 or 逐回合重算）
  - 排期：R3（纯技能迁移）之后或并行；R5/R6/R7/R8/R2 的公共地基；与 R1 无耦合
