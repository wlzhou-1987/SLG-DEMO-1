# 需求池与进度（BACKLOG）

> 状态：活文档，M6 之后唯一的进度真源。
> 历史里程碑 M1~M6 已冻结，见 [AGENTS.md §10](../AGENTS.md) 与 [GAME-DESIGN.md §10](GAME-DESIGN.md)。
> 状态标注沿用项目惯例：`✅ 已完成（日期，验收证据）`。

## 1. 工作流（一个对话完成一个 issue）

**设计对话**（一个需求一个或多个对话）：

1. 从 §3 需求池选定一条「待设计」条目（或新追加一条，一行即可不展开）
2. 按 AGENTS §9：先读 GAME-DESIGN 相关章节与 ARCHITECTURE 定位代码，再讨论方案
3. 定稿后：设计规则回写 GAME-DESIGN 对应章节；本条目状态改为「已拆解」并补齐 issue 表

**开发对话**（一个对话一个 issue）：

1. 开工：目标 issue 状态改为「开发中」
2. 按 AGENTS §5 TDD 实现，运行验收命令
3. 收尾（必须同一对话内完成）：
   - 代码提交：`feat|fix: R<需求号>-<序号> 简述`
   - 将 commit hash、日期、验收证据回填 issue 条目，状态改为已完成
   - 触及设计规则 → 回写 GAME-DESIGN；触及文件/职责/接口 → 回写 ARCHITECTURE
   - 文档以并入同一提交或紧随的 `docs:` 提交落地
4. 需求下全部 issue 完成 → 需求条目状态改为「已完成」

单点 bug 修复可建只含一个 issue 的需求条目，走轻量路径（AGENTS §2）。

## 2. 状态机与守则

- 需求条目：`待设计 → 已拆解 → ✅ 已完成`；异常出口 `搁置` / `已拒绝`（注明原因与日期）
- issue：`待开发 → 开发中 → ✅ 已完成`；异常出口 `已取消`（需求变更时注明替代者）
- 状态变更为「已完成」必须有当轮验证证据（AGENTS §6），证据不足不得标记
- 同一时间最多一个 issue 处于「开发中」（单人开发，文档一致性优先）；确需并行先征得用户确认
- 完成条目原地保留，作为版本管理台账；数量过多时再议归档
- 文件有增删的 issue 收尾时必跑 ARCHITECTURE 覆盖率检查（见 ARCHITECTURE §4）

### R4 属性体系改造（状态：待设计）
- 来源：用户提议（战前准备联动功能讨论引出，2026-09-07 设计对话进行中）
- 一句话：六维属性（HP/攻/防/速/技/运）改造为九维（HP/力量/魔力/物防/魔防/速/技/运/MP），物理/魔法分成两种伤害计算方式，引入 MP 资源限制技能/法术释放
- 设计结论（框架讨论中，定稿后回写 GAME-DESIGN 并拆 issue）：
  - 攻→力量/魔力；防→物防/魔防；速/技/运职责是否扩展随伤害计算机制讨论定——部分技能将支持以技巧/速度为伤害基数，幸运已列入讨论范围
  - 技能伤害基数（组合权重）：技能配置属性权重（如 {技巧:1, 速度:0.5}）加权合成基数；减伤轴由伤害线决定（物理线→物防、魔法线→魔防），与基数属性解耦；缺省权重取职业配置默认；支持物理+魔法双伤害叠加（算法待细化）
  - 魔法伤害公式：直接伤害 = max((魔力 × 法术伤害系数 + 法术固定伤害) × 克制系数 − 魔防, 0)；持续伤害（DoT）= 直接伤害结果 ÷ 持续回合数，每回合向上取整。法术伤害系数/固定伤害/克制系数均为法术级配置
  - 治疗量：按技能差异化公式，主要挂魔力
  - 地形效果系统（数据驱动字段化）：增益 9 项——近战物理防/近战物理闪避/远程物理防/远程物理闪避/法术防/法术闪避/HP 回复/MP 回复/额外射程；减益 5 项——回合开始直接伤害/降低护甲/降低魔防/增加 MP 消耗/回合结束附加 DoT
  - 幸运职责：回避敌方攻击、增加己方致命一击几率、降低敌方致命一击几率、其他随职业与技能设计完善——**引入暴击机制（落地时修订 §8「暴击/必杀不做」边界）**
  - 射程属性条件加成（§4.4/§4.12 原留白）随本需求落地：弓挂力量、法术挂魔力，阈值规则可配
  - MP：全员先以 MP 替代（预留怒气/能量等多资源空间，各资源恢复机制不同）；恢复途径=道具/地形/特定技能/歇息（本回合未释放任何法术——0 消耗法术亦算施放、道具不算——则下回合开始恢复，恢复量受属性与职业影响）
