# 技术选型决策记录

> 状态：**历史存档**（2026-09-04 已确认并落地）。现行技术栈的权威表述见 [AGENTS.md](../AGENTS.md) §3。

## 候选方案

| 方案 | 语言 | 上手成本 | 本机环境 | 可运行验证 | 适合场景 |
| --- | --- | --- | --- | --- | --- |
| Web（Vite + TS + Canvas/Phaser） | TypeScript | 低 | 已有 Node | 浏览器直接验证 | 2D、快速迭代 |
| Godot | GDScript / C# | 中 | 未安装 | 需编辑器 | 桌面 2D/3D |
| Unity | C# | 高 | 未安装 | 需编辑器 | 3D、大型项目 |

## 决策标准

- 能否快速跑起来并验证（DEMO 阶段最优先）
- 与目标平台匹配
- 学习价值与迁移成本

## 结论（已确认并落地，2026-09-04）

**Vite + TypeScript + 原生 Canvas**，测试用 Vitest。

- 战棋核心是网格规则与状态结算，无物理/复杂动画需求，不需要游戏引擎
- 逻辑层（战斗规则、AI、地图）与渲染层解耦，逻辑可单元测试
- 浏览器即开即玩，DEMO 验证与迭代最快

确认后的初始化步骤：`npm create vite` 建立 TS 工程 → 搭逻辑层/渲染层目录骨架 → 落地 M2 里程碑。
